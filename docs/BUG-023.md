# Reporte de Bug: BUG-023

**Ambiente:** Local (Desarrollo) / Interfaz de Administración
**Descripción:** Durante las pruebas de QA del Issue #23, se detectaron dos fallas críticas en el flujo de Offboarding:
1. **Frontend:** La lógica de la tabla en `dashboard.js` asumía de forma binaria que un usuario estaba "activo" u "offboarding". Si un usuario pasaba a estado "inactivo", la interfaz lo renderizaba erróneamente como "Activo" y volvía a habilitar el botón de offboarding.
2. **Backend:** El endpoint de la API `/api/usuarios/<id>/offboarding` no validaba el estado actual del usuario antes de proceder. Esto permitía que un usuario que ya había sido procesado (estado `offboarding` o `inactivo`) fuera enviado nuevamente, creando registros duplicados de eventos de offboarding en la base de datos.

**Severidad:** Alta (Falla lógica en el flujo principal del producto)
**Responsable:** Johan Soto
**Evidencia:** Pruebas manuales ejecutadas enviando peticiones POST repetidas al endpoint revelaron la creación de duplicados en la tabla `eventos_offboarding`. En la UI, usuarios inactivos aparecían como activos tras refrescar.
**Estado:** Resuelto (Ver PR asociado)
